State Machines

Part 3 built logic with no memory. Part 4 built memory with no logic. Put the two in a loop — flip-flops feeding gates feeding the flip-flops back — and you have the general form of every digital system there is.

5.1 The loop

A synchronous state machine is three blocks and one loop:

  • A state register — Part 4's flip-flops, holding the machine's entire memory as a bit pattern.
  • Next-state logic — Part 3's combinational gates, computing what the register should hold after the next edge, from what it holds now and what the inputs are doing.
  • Output logic — more gates, decoding the state into whatever the machine is supposed to drive.

That is the whole architecture. Everything difficult about state machines is deciding what the states should be, and this part is mostly about that decision.

5.2 What a state is

The hard step is not drawing the diagram. It is realising what has to be remembered — and the answer is almost always less than you think.

Take the standard exam machine: detect the pattern 1011 in a serial bit stream. A naive design remembers the last four bits, which needs 16 states. But the machine does not need the last four bits. It needs only how much of 1011 the input currently ends with — nothing, one bit, two bits, three, or all four. Five possibilities, five states, and the entire diagram falls out of that one sentence.

Why the backward arrows are not arbitrary

Read the states as amounts of progress and every arrow becomes derivable rather than memorised. From S3 (the input ends 101) a 0 arrives, so the input now ends 1010 — and the longest prefix of 1011 that 1010 ends with is 10, which is S2. Not S0: throwing away all the progress would miss the pattern in 101011. The same reasoning gives the arrow out of the accepting state: after a match, the trailing 1 is already the first bit of a possible next one, so it goes to S1. That is what "overlaps counted" means in hardware, and it is the detail exam questions are usually built around.

5.3 Moore and Mealy

The two forms differ in one line, and everything else follows from it:

A Moore output is decoded from the state register, and the machine does not enter the accepting state until the clock edge — so its output appears in the cycle after the bit that completed the pattern. Step the plate above through both forms and watch the Z row: the same input, the same detections, one column apart. Questions asking "in which clock cycle does the output assert" are testing exactly this, and the answer depends on which machine you were handed.

Which one should you build?

In practice, Moore — unless you need the answer a cycle early. A registered output is one you can route anywhere without worrying about what it does mid-cycle, and Part 6 is a catalogue of what goes wrong when you cannot make that assumption. The usual compromise is a Mealy machine with its output put through one flip-flop, which is clean again but has given back the timing advantage — at which point you have built a Moore machine with extra steps. Mealy is never larger; Moore is never faster.

5.4 The design procedure

Six steps, each consuming the one before it. Written out, it is completely mechanical — which is the point, because the only creative step is the first.

Worked · from behaviour to gates

  1. State diagram. Decide what has to be remembered, and name each state by its meaning. This is the only step requiring thought, and the only one where a real mistake can be made.
  2. State table. The same information as rows: present state, input, next state, output. Mechanical, and it is where a missing transition becomes visible.
  3. State assignment. Give each state a bit pattern. ⌈log₂N⌉ flip-flops for a binary assignment, or one per state for one-hot. §5.5 is about this choice.
  4. Excitation table. Translate each transition into flip-flop inputs, using Part 4's tables. With D flip-flops there is nothing to do — the next-state column is the D column.
  5. Minimise. One Karnaugh map per flip-flop input and one per output, over the state bits and the machine's inputs. Part 3, unchanged.
  6. Draw the gates. Nothing is left to decide.

An exam question typically hands you step 2 or 3 and asks for step 5. Knowing the whole sequence is what tells you what you have been given — a table headed "next state" needs no excitation step if it says D flip-flops, and needs Part 4's JK table if it does not.

5.5 State assignment

Step 3 looks like bookkeeping and is not. The machine's behaviour does not depend on which pattern you give which state; the amount of hardware very much does.

There is no rule, and that is the finding

The plate above tries all 24 ways of dealing four codes to four states and minimises each. The binary assignment costs 9 literals, Gray costs 18 — worse, for this machine — and the best of the 24 costs 7. No heuristic predicts which one wins, because the answer depends on the machine's transition structure rather than on any property of the codes. This is why synthesis tools search rather than follow a rule, and why "state assignment is arbitrary" is the one wrong answer: it is free, in that any assignment works, but it is not without consequence.

5.6 Reset, and the states you did not draw

Two failure modes that questions like, and that a careful design closes:

  • Power-up is undefined. Each flip-flop settles wherever it settles, so a machine without a reset spends its first cycles in a state nobody chose. Every real design has a reset for this reason alone.
  • Unused codes are reachable. Five states in three flip-flops leaves three codes unaccounted for. Treating them as don't-cares gives the smallest equations — and leaves their behaviour to whatever the gates happen to do, which can be a loop the machine never escapes. A self-starting design gives every unused code an explicit route back.
Both answers are correct, to different questions

A minimisation question wants the unused states treated as don't-cares, because that is what makes the Karnaugh map smaller and it is the standard exercise. A design question wants them routed to reset. Read which one is being asked — the giveaway is whether the question says "minimise" or says "self-starting" / "fault-tolerant".

5.7 What to memorise from this part

Know cold

  • The architecture: state register + next-state logic + output logic, in a loop closed by the clock.
  • Moore: Z = g(S). Mealy: Z = g(S, X). Everything else follows.
  • Moore needs one more state and asserts one cycle later; its output is registered and clean.
  • A state records how much progress has been made, not the input history. A k-bit pattern needs k+1 Moore states, k Mealy.
  • Design order: diagram → table → assignment → excitation → minimise → gates.
  • D flip-flops need no excitation step, because D = Q⁺.
  • Binary: ⌈log₂N⌉ flip-flops. One-hot: N, with trivial logic.
  • Unused codes must be routed somewhere, and every machine needs a reset.

A state machine is Part 3's gates and Part 4's flip-flops wired into a loop, and the only genuinely difficult step is deciding what a state means. Get that right — "how much of the pattern the input currently ends with" — and the diagram, the table, and every backward arrow follow without invention.

Everything after that is mechanical, and the one place judgement returns is the state assignment. The plate's search says the same machine costs anywhere from 7 to 18 literals depending on nothing but which pattern you gave which state, with no rule predicting the winner. That is a fair picture of digital design in general: the structure is forced, the encoding is free, and the free choices are where all the remaining cost lives.
