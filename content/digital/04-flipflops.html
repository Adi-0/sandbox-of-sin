Flip-Flops and Counters

Everything so far has been combinational: outputs depend only on the inputs present right now. This part adds the one ingredient that changes the subject entirely — a circuit that remembers.

4.1 The line that divides the module

A gate has no history. Put 1 and 0 into an AND gate and you get 0, and it will give you 0 every time regardless of what came before. That is the defining property of combinational logic, and it is what Parts 2 and 3 have been about.

Sequential logic breaks that property deliberately, by feeding an output back to an input. Once a value can influence itself, the circuit's output depends on its own past — and past is memory.

The whole idea, in one sentence

Cross-couple two NOR gates — each one's output driving the other's input — and the pair has two stable arrangements. Both are self-consistent, so once it is in one it stays there with no input at all. That is a stored bit, built from nothing but Part 2's gates, and every flip-flop and register on this exam is a refinement of it.

4.2 Latch against flip-flop

The cross-coupled pair above is a latch: it responds to its inputs whenever they change. That turns out to be inconvenient, because a circuit whose memory updates continuously is hard to reason about — the output feeds logic that feeds the input again, and the timing decides the answer.

The fix is to give the memory a moment at which it is allowed to change, and to keep it deaf the rest of the time. That moment is a clock edge, and a memory that only listens on an edge is a flip-flop.

4.3 The four types, and what separates them

Four flip-flops appear on the exam. They differ only in how their inputs decide the next value, so the honest way to learn them is to watch one edge at a time rather than memorise four tables.

Trap · the forbidden state, and why JK exists

Driving an SR flip-flop with S = R = 1 tells it to set and reset at once. Both outputs go to the same level — so Q and Q̄ are no longer complements, and the device is not in a legal state at all. Worse is what follows: when the inputs return to 0, whichever gate is fractionally faster decides where it lands, so the settled value is unpredictable. Load SR on the plate and walk to edge 5 to see both halves of that. The JK's entire contribution is to take that same combination and define it as toggle — which, not coincidentally, is also what makes a JK able to count.

4.4 Excitation — the table read backwards

A characteristic table answers "given the inputs, what does Q do?" Designing a counter or a state machine asks the reverse: given the transition I need, what must the inputs be? That is an excitation table, and it is the bridge into Part 5.

Worked · the JK excitation table, derived rather than memorised

Take the transition Q: 1 → 0. Which J and K produce it?

  1. Q must end at 0, and it is currently 1 — so the flip-flop must either reset or toggle. Both are available.
  2. Reset needs J = 0, K = 1. Toggle needs J = 1, K = 1.
  3. K = 1 in both cases; J differs. So K = 1 and J is a don't-care: J = ×, K = 1
  4. The same argument on the other three rows completes the table:
TransitionJKBecause
0 → 00×Must not set. Resetting a 0 changes nothing, so K is free.
0 → 11×Must set. With K = 1 it toggles to 1, with K = 0 it sets to 1 — either reaches 1.
1 → 0×1Must reset. J = 1 toggles to 0, J = 0 resets to 0.
1 → 1×0Must not reset. Setting a 1 changes nothing, so J is free.

Every row has a don't-care, and that is the point of the whole table. Those × entries go straight into Part 3's Karnaugh maps and routinely halve the input logic — which is the historical reason JK flip-flops were worth their extra pin.

Why modern design uses D anyway

A D flip-flop's excitation table is D = Q⁺ and nothing else — the excitation logic is the next-state logic, with no translation step and no don't-cares to exploit or misplace. When gates were expensive the JK's don't-cares were worth the extra design work; once they were free, the simpler device won. The exam still asks about JK, because the excitation idea is clearest there, but every flip-flop in an FPGA is a D.

4.5 Counters

Tie a T flip-flop's input high and it toggles on every clock edge — one output transition per two input edges, which is a divide by two. Chain the divisions and you have a binary counter, because dividing by two repeatedly is what counting in binary is.

Trap · 2ⁿ against 2n

A 6-bit counter clocked at 32 MHz gives 32 / 64 = 0.5 MHz at its top output — not 32 / 12. Stages multiply their divisions; they do not add them. Every distractor list on this topic contains the addition.

4.6 What a ripple counter costs

The chain described above is a ripple counter: the clock reaches only the first flip-flop, and each stage clocks the next. It is the cheapest possible counter — no steering logic at all — and the plate below shows the bill.

The glitch is the real problem, not the speed

Take a 4-bit ripple counter from 0111 to 1000. Q0 clears, and its edge clocks Q1, which clears and clocks Q2, and only then does Q3 set. The output pins therefore read 0111 → 0110 → 0100 → 0000 → 1000, and every one of those intermediate values is genuinely present and genuinely decodable. A gate watching for 0100 will fire a spurious pulse on a transition that never went anywhere near it. This, more than the frequency limit, is why decoded outputs need a synchronous counter — or a strobe that samples only after the count has settled.

A synchronous counter clocks every flip-flop from the same edge and tells each stage whether to toggle: stage k toggles only when all the bits below it are 1, which is an AND of k inputs. Settling then takes one stage delay whatever the width, and the outputs move together, so the count is never briefly wrong. The trade is gates for time, and it goes the same way in almost every real design.

4.7 Registers

Flip-flops side by side, sharing one clock, are a register — an n-bit value updated in a single edge. Wire each output into the next one's input instead, and it becomes a shift register, moving its contents one place per clock. Three uses are worth recognising:

  • Serial to parallel and back — the standard way a one-wire link becomes a byte.
  • Multiply and divide by two — a left shift doubles, a right shift halves, which is why shifts are cheap instructions.
  • Ring and Johnson counters — feed the last output back to the first. A ring counter of n stages has n states with one bit set; a Johnson counter feeds back the complement and gets 2n. Both trade flip-flops for the decoding logic a binary counter needs.
Counting the states of a ring counter

A 4-stage ring counter has 4 states, not 16 — it is deliberately using only the one-hot patterns. A 4-stage Johnson counter has 8. Both are wasteful of flip-flops and generous with everything else: no decoding gate is ever needed, because each state is already a single wire. Questions on this topic are testing whether you noticed that "n flip-flops give 2ⁿ states" describes a binary counter, not every counter.

4.8 What to memorise from this part

Know cold

  • Latch is level-sensitive, flip-flop is edge-triggered. Assume edge-triggered unless told otherwise.
  • Q⁺ = D; Q⁺ = T ⊕ Q; Q⁺ = J·Q̄ + K̄·Q.
  • S = R = 1 is forbidden; J = K = 1 toggles. That single difference is what the JK is for.
  • JK excitation: 0→0 is J=0,K=×; 0→1 is J=1,K=×; 1→0 is J=×,K=1; 1→1 is J=×,K=0. Every row has a don't-care.
  • n = ⌈log₂N⌉ flip-flops for mod-N, and f_out = f_in / 2ⁿ.
  • Ripple counter settles in n · t_pd; synchronous settles in one stage at any width.
  • Trim a mod-N counter by decoding N, not N−1.
  • Ring counter: n states. Johnson counter: 2n.

Feed an output back to an input and the circuit acquires a past. Gate it with a clock edge so that the past only updates at known instants, and the result is a flip-flop — the entire content of this part, and the only structure Part 5 will need to add to Part 3's combinational logic.

Everything else here is arithmetic on that one device. Chaining toggles counts in binary, so n flip-flops give 2ⁿ states and the last one divides by 2ⁿ. Letting each stage clock the next makes the counter free and its delays cumulative; clocking them all together costs gates and buys a settling time that no longer depends on how wide the counter is. That trade — hardware for timing certainty — is the shape of nearly every decision in synchronous design, and it is the same one again in Part 6.
