Number Systems

Everything a digital system does is arithmetic on patterns of two symbols. This part is about reading those patterns fluently, and about the one representation choice that made hardware simple.

1.1 Bases are groupings, not conversions

A number does not have a base. Notation has a base, and the number is whatever it is. Once that clicks, "convert 53 to hex" stops being a procedure and becomes reading:

The module's number

This module runs on 53, for a reason worth checking rather than taking on trust. In binary it is 00110101; its two nibbles are 0011 and 0101, so in hex it is 0x35 — the digits 3 and 5. And it has exactly 4 bits set. The 3-4-5 triangle that has run through this compilation since Mathematics Part 1, and whose angle is 53.13°, turns out to be sitting inside the number 53 as well.

1.2 Representing negatives

Bits have no minus sign, so a convention is needed. Three exist, and only one survived:

  • Sign-magnitude — top bit is the sign, the rest is the size. Simple to read, and it has two zeros. Addition needs to compare signs first.
  • One's complement — negate by inverting every bit. Still two zeros, and addition needs an end-around carry.
  • Two's complement — invert every bit and add one. One zero, and addition needs no special case at all.
Trap · carry is not overflow

They are different flags answering different questions. Carry out means the result exceeded the unsigned range. Overflow means it exceeded the signed range. The same addition can set one, both, or neither — and which one matters depends entirely on how you have decided to read the bits, which the hardware cannot know. Adding 0x80 + 0x80 produces a carry and an overflow; adding 0x7F + 0x01 produces an overflow and no carry.

Worked · subtracting by adding

Compute 53 − 20 in 8-bit two's complement, using addition only.

  1. Write both in binary: 53 = 00110101, 20 = 00010100
  2. Negate 20 — invert, then add one: −20 = 11101100
  3. Add: = 1 00100001
  4. Discard the ninth bit. The result is 00100001 = 33 ✓

That discarded carry is not an error — it is the wheel going round. The whole scheme is designed so that the overflow off the top lands exactly where the answer needs it to.

1.3 Codes that are not weighted

Not every bit pattern is a positional number. Two encodings appear on this exam:

  • BCD — each decimal digit stored in its own four bits. 53 becomes 0101 0011, which is not 0x35. Wasteful, and used where the display matters more than the arithmetic.
  • Gray code — consecutive values differ in exactly one bit. Used on rotary encoders and in K-maps, both for the same reason: a single-bit change cannot be misread during a transition.
Gray code appears again in two parts' time

The row and column ordering of a Karnaugh map in Part 3 is Gray code — 00, 01, 11, 10 — and that ordering is the only reason adjacent cells can be grouped. It is not a decoration; without it the map does not work.

1.4 What to memorise from this part

Know cold

  • Powers of two to 2¹⁶: 256, 1024, 4096, 65 536.
  • 4 bits = 1 hex digit, 3 bits = 1 octal digit.
  • Two's complement: invert and add one; range −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1.
  • Carry ≠ overflow. Carry is unsigned, overflow is signed.
  • BCD is one nibble per decimal digit, and is not hex.
  • Gray code changes one bit at a time.

A number has no base; notation does. Hexadecimal and octal exist because 16 and 8 are powers of two, so their digits are just bits in groups — which makes them shorthand rather than a different system.

Two's complement won because it makes subtraction disappear. Negation is invert-and-add-one, the wheel closes so there is only one zero, and the same adder handles both operations — at the price of a range that is asymmetric by exactly one.
