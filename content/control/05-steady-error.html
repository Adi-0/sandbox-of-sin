Steady-State Error and System Type

A loop can be perfectly stable and still settle in the wrong place. This part is about the gap that is left when everything has stopped moving — where it comes from, how to compute it in one limit, and why one structural feature of the plant decides whether it exists at all.

5.1 The gap, in one limit

For unity feedback the error signal is the command minus the output, and Part 1 already gave its transfer function:

E(s) = R(s) / (1 + G(s))

Linear Systems Part 3's final value theorem turns that into a number without inverting anything:

e(∞) = lim (s→0) sR(s) / (1 + G(s))

Everything else in this part is that one expression evaluated for the three inputs the exam uses. Which one you get depends on a race: the s on top going to zero, against G(s) below blowing up if it has poles at the origin. Who wins is the whole subject.

Trap · the theorem lies about unstable systems

The final value theorem is only valid when the final value exists — that is, when every closed-loop pole is in the left half-plane. Apply it to an unstable loop and it returns a perfectly respectable-looking number for a signal that is actually growing without bound. Check stability first, with Routh if you have to. On an exam this is usually safe; in a question that gives you a gain near the boundary, it is the trap being set.

5.2 Type is a count of integrators

System type is the number of open-loop poles at the origin — the power of s standing alone in the denominator of GH. Not the order, not the number of poles, just how many integrators the signal passes through on its way round.

Why an integrator kills the error

Think about what a plant with no integrator has to do to hold its output at 5. Its output is proportional to its input, so its input must be a steady non-zero number — and its input is the error. A type-0 loop needs a permanent error to hold a permanent output. The error is not a defect, it is the command. Put an integrator in the forward path and that changes completely: an integrator's output stays where it is when its input is zero, so the loop can sit exactly on the command with nothing driving it. That single sentence explains the whole table below.

5.3 What raising the gain costs

For a type-0 loop the only lever available is K, and it works: the error is 1/(1+Kp) and Kp is proportional to K. The problem is what else K is attached to.

Worked · a specification that proportional gain cannot meet

A unity-feedback loop has G(s) = K/[(s+1)(s+2)(s+4)]. The steady-state error to a step must be no more than 5%. Find the gain — and then check it.

  1. Error to Kp. 1/(1+Kp) = 0.05 → Kp = 19
  2. Kp to K. K = 8 × 19 = 152
  3. Check stability, which Part 3 makes cheap. The characteristic equation is s³ + 7s² + 14s + (8+K), stable while 8 + K < 98, so K < 90.
  4. 152 > 90. The gain that meets the error specification makes the loop unstable. There is no answer.
  5. How close can it get? At the very boundary, K = 90 gives e = 8/98 = 8.2% — and that is with zero margin and a response that never settles. A sane design at K = 20 gives 29%.

This is not a contrived example; it is the normal situation. Proportional gain is one number being asked to set accuracy, damping and stability at once, and beyond a certain point those demands are simply incompatible. The way out is not a cleverer value of K. It is to add an integrator — which turns the loop from type 0 to type 1 and makes the step error exactly zero at any gain. That is what the I in PID does, and it is Part 6.

The constants assume unity feedback

Kp, Kv and Ka are defined for a loop whose feedback path is a plain wire. If H is a sensor with its own gain or dynamics, the quantity being driven to zero is R − HC, not R − C, and the table does not apply directly. Go back to E/R = 1/(1+GH) and use the final value theorem on that — it always works, and it is only one more line. Worth knowing because a question that quietly puts a 0.1 in the feedback path is testing exactly this.

5.4 What to memorise from this part

Know cold

  • e(∞) = lim sR/(1+G) — and only if the loop is stable.
  • Type = poles at the origin, not order.
  • Kp = G(0), Kv = lim sG, Ka = lim s²G.
  • e = 1/(1+Kp) — the 1 + appears here and nowhere else. Ramp is 1/Kv, parabola 1/Ka.
  • Type n tracks inputs up to order n exactly; one order past gives a constant error, two gives an unbounded one.
  • Raising K shrinks a type-0 error but never removes it, and costs margin every time.
  • An integrator removes it outright — and that is what makes PI control the standard answer.

Two different questions have now been asked of the same loop. Parts 3 and 4 asked whether it settles; this part asks whether it settles in the right place, and the answer turns out to depend on something completely different — not on the gain, not on the pole locations, but on how many integrators the loop happens to contain. A structural property, countable at a glance, decides which commands can be followed exactly and which cannot be followed at all.

And the two questions pull against each other. The gain that makes the error small is the gain that ruins the damping, and on a real third-order plant the two specifications can be flatly incompatible — as the worked example was. The resolution is to stop using one knob for two jobs. Part 6 adds a term that acts on the accumulated error, which fixes the accuracy outright, and a term that acts on its rate of change, which buys back the damping. Those three terms are the controller almost every plant in the world is running.
